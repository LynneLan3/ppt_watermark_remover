# 2026-04-27 修复 Vercel Preview analyze 404 错误

## 任务目标
修复 Vercel Preview 环境中 PDF 上传后 POST /api/jobs/[jobId]/analyze 返回 404 的问题。

## 问题分析
根本原因：Vercel serverless 函数是无状态的，每次请求可能运行在不同的实例上，导致使用本地文件系统（/tmp）存储 job 状态会丢失。当 analyze 请求到达时，找不到之前创建的 job。

## 关键实现说明

### 1. Blob-backed Job Storage

```typescript
// lib/blob-storage/job-store.ts
export async function readJob(jobId: string): Promise<JobRecord> {
  const pathname = getJobManifestPathname(jobId);
  const response = await get(pathname, { access: "private" });
  if (!response || response.statusCode !== 200) {
    throw new JobNotFoundError(jobId);
  }
  const text = await streamToText(response.stream);
  return JSON.parse(text) as JobRecord;
}

export async function writeJob(job: JobRecord): Promise<void> {
  const pathname = getJobManifestPathname(job.jobId);
  await put(pathname, JSON.stringify(job, null, 2), {
    contentType: "application/json",
    access: "private",
  });
}
```

## SOP 候选规则

1. **Serverless 状态持久化**：在 Vercel 等 serverless 环境中，必须使用外部存储（Blob/DB）持久化状态，不能依赖内存或本地文件系统跨请求。

2. **错误码规范**：API 应该区分不同类型的错误：
   - 404 JOB_NOT_FOUND: jobId 不存在或已过期
   - 409 UPLOAD_NOT_FINALIZED: job 存在但上传未完成

3. **结构化日志**：API 路由应该记录请求生命周期：start, complete, error，包含 jobId、durationMs、status 等字段。

4. **存储抽象**：提供统一的存储接口，根据环境自动选择合适的后端（开发用本地文件系统，生产用 Blob）。
